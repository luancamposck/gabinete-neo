## Codebase Patterns
- Survey management authorization should preserve the existing OWNER bypass and use `hasMembershipPermissionService` with `PERMISSIONS.SURVEYS_MANAGE` for non-owner members.
- The mandatory Ralph quality gate is blocked by Biome errors, but Biome warnings can remain without failing `fix:biome` or `lint:biome`.
- Survey question and option ordering should be normalized from UI array order and persisted as base-1 positions (`index + 1`) to stay aligned with the database constraints.
- Public survey submission must treat unauthenticated and anonymous as separate concerns: fingerprint dedupe applies to both, but `is_anonymous` should only be `true` when the respondent explicitly chooses anonymity.
- Cross-table survey integrity that cannot be expressed with a plain foreign key should be enforced with a dedicated Postgres trigger, while letting existing FKs keep ownership of missing-parent errors.
- Survey read RLS should anchor child-table visibility (`survey_questions`, `survey_question_options`) to the parent survey chain instead of duplicating availability and membership predicates in every table policy.
- When enabling RLS on write-only survey flows, prefer `INSERT` operations without `.select()` and generate IDs in the application layer so raw response tables do not need extra `SELECT` policies just to return inserted rows.
- Safe survey response views should be the single place that masks both `respondent_user_id` and manual respondent snapshot fields for anonymous submissions, while preserving identified public snapshots for authorized result consumers.
- Survey module code should prefer aliases from `src/modules/surveys/shared/types/db.ts` over inline `TablesInsert<T>` or enum lookups so schema drift is absorbed in one place.
- Survey server actions should map Supabase rows into camelCase DTOs from `src/modules/surveys/shared/types/dto.ts` so UI-facing contracts stay stable even when database columns remain snake_case.
